# WX BRF（ヘリ運航 気象ブリーフィング補助）

フライト前の気象ブリーフィングをスマホで確認するPWA。

公式の気象ブリーフィングの補助です。飛行可否の最終判断には使わないでください。

## ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | アプリ本体（HTML・CSS・JSを1ファイルに。ビルド不要） |
| `sources.json` | 取得元URLの定義。気象庁のURLが変わったらここだけ直す |
| `sw.js` | Service Worker。オフライン表示用のキャッシュ |
| `lib/metar.js` | METAR/TAFのパーサと日本語デコード（純粋関数） |
| `lib/judge.js` | ミニマ判定とTAFの時間軸展開（純粋関数） |
| `lib/sounding.js` | 鉛直プロファイルの計算（LCL・CAPE・SSI・0℃高度など。純粋関数） |
| `lib/charts.js` | メテオグラム・予報断面図・Skew-Tの描画（Canvas） |
| `lib/ai.js` | AI解説の入出力（プロンプト作成・匿名化・返事のJSON読み取り。純粋関数） |
| `lib/signals.js` | 総合解析（資料の突き合わせ）とブリーフィング台本の組み立て（純粋関数） |
| `lib/route.js` | 経路の分割・通過時刻・区間判定・共有コードの取り込み（純粋関数） |
| `lib/verify.js` | 予報の答え合わせ（予報と実測の突き合わせ・ずれの集計・補正。純粋関数） |
| `tests/` | 上の2つの単体テスト。`node --test tests/` |
| `japan.json` | 日本の輪郭（Natural Earth 1:50m、パブリックドメイン）。週間の地上予想図で日本を強調するのに使う |
| `manifest.json`・`icon-*.png` | PWAの設定とアイコン（`python3 tools/gen_icons.py` で作り直せる） |

## 更新するとき

`index.html` などを変えたら、次の3つを一緒に上げる（上げないと端末に更新が届かない）。

| 場所 | 定数 |
| --- | --- |
| `sw.js` 先頭 | `VER` |
| `index.html` | `VER_TAG` |
| `index.html` | `BUILD`（更新日） |

手元で確認するときも、Service Workerが古い `index.html` を返し続ける。VERを上げてから2回再読み込みする。

## 手元で動かす

```bash
python3 -m http.server 8765
```

ブラウザで <http://localhost:8765> を開く。

## フェーズ1 動作確認手順

受入条件：スマホで全画面が表示され、各図に発表時刻が出る。機内モードでも最後のデータが見られる。

1. **ホーム（0）**：府県予報区の一覧が出る。飛行予定・飛行場・府県予報区を変えて再読み込みしても残っている
2. **画面の移動**：左右スワイプ、下の「前／次」ボタン、上のタブの3通りで移動できる。再読み込みすると最後に見ていた画面が開く
3. **総観（1）**
   - 地上天気図（実況）に発表時刻と対象時刻が出る
   - 高層天気図・解析図3枚（AUPQ35・AUPQ78・AXFE578）が画像で出て、更新時刻と解析時刻が出る
   - 図をタップすると全画面になり、ピンチで拡大、ドラッグで移動、ダブルタップで拡大／戻す
   - ひまわり：バンドを切り替えられ、スライダーと▶で直近2時間を動かせる
   - 全国航空気象解説報が出る。「短期予報解説資料 表示する」でPDFが画像で出る
4. **レーダー実況（2）**：直近1時間のナウキャストをスライダーと▶で動かせる。雷のチェックを外すと雷の表示が消える
5. **レーダー予想（3）**：スライダーの左端が「+5分」、右端が「+15時間前後」。途中で「ナウキャスト」→「短時間予報（速報）」→「短時間予報」に切り替わる
6. **明日の予想（7）**
   - 地上予想天気図：24h・48hを切り替えられ、対象時刻が出る
   - 電計資料の予想図（極東 地上気圧・500hPa、極東 850hPa・700hPa、日本 850hPa相当温位）が出る。12・24h／36・48h／72h を切り替えられ、初期値と各予想時間の対象時刻（JST）が出る
   - 府県天気予報（天気・風・波）が出る
7. **週間（8）**
   - 地上予想図（週間）が最初に出る。上に大きい図、下にサムネイルが対象時刻の順に並ぶ（スマホで1行4枚）。気象庁の実況・24h・48h天気図（水色の時刻）が先に、その後に**48h予想の翌日から**の週間天気図（FEAS）の下段の日本付近が、それぞれ時刻順に並ぶ（天気図と同じ日付の週間天気図は出ない）
   - FEASの図は気象庁の天気図と同じ向き（東経140度が真上）に回してあり、日本が赤く塗られ、海岸線とずれていない。下の隅がわずかに白い
   - サムネイルを押す、または◀▶で大きい図が切り替わる。大きい図はタップで全画面
   - その下に週間天気図（500hPa・地上の2段）が出る
   - 週間天気予報の表が出る。ホームで府県予報区を変えると、この画面を開き直したときに変わっている
8. **古いデータ**：発表から時間が経った図は発表時刻が黄色になり「古いデータ」と出る。ホームの「データの状態」にも「古い」と出る
9. **オフライン**：一度全画面を開いたあと、アプリを閉じて機内モードにして開く
   - 画面が起動し、見た図がそのまま出る
   - 取得時刻の横に「（オフライン：前回取得分）」と黄色で出る。ホームの「データの状態」は「前回分」になる
   - 見ていない範囲の地図・レーダーは出ない（取得済みの範囲だけ）
10. **判定バッジ**：フェーズ1ではすべて灰色の「データなし」（GOにならない）

## フェーズ2 動作確認手順

受入条件：過去のMETAR/TAF数十件でデコードと判定が手計算と一致する。欠測時にGO表示にならない。

1. **単体テスト**：`node --test tests/` がすべて通る（36件）
2. **設定**：画面5の「ミニマと判定の設定」に値を入れて保存。ホームで出発・帰投予定と飛行場（例 `RJTT RJAA`）を入れる
3. **中継**：「中継の設定」でURLと合言葉を入れ、「接続テスト」で「つながりました」と出る。公開アドレスか `http://localhost:8765` からだけ使える（LANのIPアドレスからは中継側で拒否される）
4. **表示**：飛行場ごとにMETARとTAFの原文が出る。要素をタップすると日本語が出る。解析できない要素は黄色の点線で「未解析」と出る
5. **判定**：各要素の値・理由・バッジが出る。TAFは判定する時間帯を1時間ごとに、どの群（本体・BECMG・TEMPO・PROB・FM）のどの要素が引っかかったかが出る。TEMPO・PROBのミニマ未満は「注意」。1,000ft以下のSCTは「低い雲(SCT)」として注意（高さは設定で変更可）
   - VMC/SVFR/IMC：METARの見出しに緑VMC・オレンジSVFR（IMCだが地上視程1,500m以上）・赤IMC（1,500m未満）と理由。TAFの見出しと1時間ごとの表に本体の状態、TEMPO・PROBだけで悪くなる時間は点線で「TEMPO SVFR」「一時 IMC」など
6. **手計算との照合**：過去のMETAR/TAFを数十件貼り付け、雲底・視程・風・横風・天気の判定を手計算と比べる
7. **欠測**：`METAR RJxx 170500Z AUTO /////KT //// ////// 20/10 Q////` を貼ると灰色（GOにならない）。90分より古いMETARも灰色
8. **貼り付け**：写真アプリのテキスト認識でコピーした電文を貼ると「手入力 hh:mm取込」と出る。ホームに無い飛行場は自動で足され、「手入力のみ（中継に送らない）」になる
9. **ホーム**：画面5を開かなくても「各画面の判定」の5に判定が出る。総合は判定の出ていない画面があるうちは「データなし」

## フェーズ4（画面6）動作確認手順

受入条件：自作の断面図を、公式の飛行場時系列予報がある空港で比べて傾向が合うこと。

1. **単体テスト**：`node --test tests/` がすべて通る（81件。うち鉛直計算17件は標準大気・湿度表・エマグラムの値と照合）
2. **位置**：画面6で飛行場を選び、緯度・経度を入れて保存すると数値予報を取りに行く（標高と取得時刻が出る）
3. **メテオグラム**：気温・露点、地上風の矢羽、雲量（上から上層・中層・下層）と推定雲底、降水量、海面気圧、SSI（線）とCAPE（棒）が48〜72時間ぶん出る。飛行予定の時間帯が水色の帯で出る。METARがあれば実測の気温・露点が点で重なる
4. **断面図**：相対湿度の塗り（90%以上が濃い青）、各層の矢羽、0℃高度の破線、飛行時間帯の枠、上に推定の判定色帯
5. **Skew-T**：時刻スライダーで動かせる。気温・露点・気塊の経路とLCL、乾燥断熱線・湿潤断熱線・等飽和混合比線、右端に各層の矢羽
6. **判定材料**：SSI・LI・CAPE・LCL・推定雲底・0℃高度・湿潤層・逆転層・シアーが数値と色で出る
7. **公式との比較**：同じ飛行場の気象庁 飛行場時系列予報（画面5）と並べて、雲底・風・降水の傾向が合うか見る
8. **答え合わせ**：画面6の「予報の答え合わせ」に、予報と実測のずれ（予報−実測）がリード時間帯ごとに出る。画面6を開くと予報が、画面5でMETARを取ると実測（過去3時間ぶんを含む）が記録される。雲底の記録が10件を超えると「推定雲底に補正をかける」が使えるようになり、ONにするとメテオグラム・断面図の推定雲底が中央値のずれのぶん補正される。記録は端末内のみ
9. **学習モード**：各画面の見出しの右にある「学習モード」ボタンでON/OFFできる（ホームの設定でも可）。ONにすると、画面1に高層天気図の見どころ、画面5にMETAR/TAFの見どころ、画面6に「雲が残る雲か発達する雲か」の見分け方と用語の説明が出る。画面2・3にレーダーの見どころ、画面4に経路判定の見どころ、画面7に予想図の見どころ、画面8に週間の見どころが出る。画面6の「Skew-Tで強調」ボタンで、逆転層・湿潤層・気塊の浮力（CAPEの面積）が図の上で色分けされる。切り替えても同じ画面のまま（横スクロールがずれない）

## フェーズ4（画面4 経路）動作確認手順

1. **経路を作る**：地図をタップして点を置く。ドラッグで移動、点をタップで削除。「最後の点を消す」「全部消す」も動く
2. **取り込み**：ナビPWAの共有コード（HNAV1.…）かJSONを貼ると点が入る
3. **判定**：「判定する」で区間ごとに数値予報を取り、雲底・地形・降水・風・着氷・山岳の判定が表に出る。経路が判定の色で塗り分けられる
4. **条件**：対地速度・飛行高度・区間の長さ・各しきい値を変えると判定が変わる。出発時刻はホームの出発予定
5. **下層悪天予想図**：詳細版（地域→図を選択）と通常版（地域・予想時間）が出る
6. **気象変換点（峠）**：地図の橙の十字（中心。下に座標が出る）を峠に合わせて「十字の位置を追加」→ 名前を入れると、地理院の標高（1mレーザー測量）が自動で入る。推定雲底が「峠の標高＋間隔」より上かで判定が出る。視程は判定せず「カメラで確認」と出る
7. **ライブカメラ**：「カメラを追加」で画像の直リンク（.jpg など）を登録すると画像が並ぶ。ページのURLを入れた場合はタップで元ページが開く。長押し（右クリック）で削除。URLは端末内のみ
8. **写真**：「写真を追加」で経路予報の写真を端末内に保存。タップで拡大、長押し（右クリック）で削除
9. **レーダー**：画面2・3の地図に経路が桃色の破線で重なる
10. **ホーム**：「各画面の判定」の4に結果が出る

## 画面9（まとめ）動作確認手順

1. **作成**：画面9を開くと、飛行場のMETAR/TAF・数値予報・経路の判定を集めて、総合解析と台本を作る（「情報を集めて作る」で作り直し）
2. **総合解析**：天気の下り坂／雷・にわか雨／霧・低い雲／強風・乱気流／前線の通過／経路の弱いところ／資料の食い違い が、根拠つきで出る。根拠の「画面◯」を押すとその画面へ飛ぶ
3. **台本**：各行に画面番号が付く。「コピー」でクリップボードへ、「読み上げ」で音声読み上げ（端末が対応していれば）
4. **食い違い**：TAFの雲底と数値予報の推定雲底が1,500ft以上違うと「気象担当者に確認」のバッジが出る
5. **ホーム**：3行要約に、台本の先頭3行が出る

## AI解説（手貼り）の使い方と確認手順

APIキーが無くても、Claudeなどのチャットに貼るだけで使えます（無料）。公開後は中継経由の自動取得に差し替えます。

1. 画面9を開き、「AI解説」の**Claudeで開く**（スマホ向け。プロンプト入りでClaudeが開く）か**プロンプトをコピー**を押す
   - 既定で飛行場コードを「地点A」に伏せて送る。「送る内容を見る」で確認できる
   - 「短く送る」をONにすると電文の原文を外して約2,600文字になり、リンクで開ける長さに収まる（OFFは約3,300文字でコピーに切り替わる）
2. Claudeの返事（JSON）をコピーし、アプリに戻って**クリップボードから貼り付け**→「取り込む」
3. 各画面の上に「話すポイント（AI解説）」が根拠つきで出る。ホームの3行要約もAIの文章に変わる
4. 資料が新しくなると「資料が更新されています」と出るので、作り直す
5. おかしなJSONは理由つきで断る。根拠(basis)が無い画面があれば警告が出る
